# Target-role capability map

The project should produce visible evidence for the role rather than merely list technologies.

| Capability | Project evidence |
|---|---|
| Full-stack product ownership | TypeScript UI, Python API, lakehouse, local deployment, health checks, tests, and runbook |
| Product judgment | Problem brief, explicit non-goals, user decisions, acceptance criteria, and revision history |
| Unified data model | Collaborative bus matrix, conformed dimensions, tested facts, glossary, and shared definitions for steam delivery, availability, revenue, and shortfall |
| SQL and dbt | Source freshness, model contracts, relationship tests, energy-balance checks, lineage, and CI |
| Time-series and IoT | Live simulated plant telemetry plus historical intervals, late events, sensor errors, and revisions |
| Batch and streaming | Airflow REST backfills plus IRIS/Redpanda/Spark event path converging in Iceberg |
| Business-system integration | Customers, effective-dated contracts, commitments, work orders, and billing joined to operational events |
| Self-service | Governed metric/alert editor with preview, validation, ownership, and approval tiers |
| Security | Operator/commercial/customer roles, site isolation, protected rates, audit log, and negative tests |
| AI product | Read-only investigation assistant using approved metric and incident tools |
| Proactive AI guardrails | Authorization per call, citations, golden questions, injection tests, leakage tests, tool-error tests, and cost/latency tracking |
| Reliability and observability | Airflow retries, stream lag, freshness, structured logs, trace IDs, SLOs, and recovery runbook |
| Engineering standards | Typed contracts, linting, unit/integration/end-to-end tests, CI gates, ADRs, PR template, and contribution guide |
| Collaborative development | Workshop decisions and feedback from domain practitioners or representative users |
| MCP/plugin APIs | Stretch: expose the same read-only governed tools through MCP |
| ClickHouse | Implemented rebuildable serving layer after measuring direct Trino/R2 product latency; versioned native tables, final ready marker, exact retry, and read-only tenant-scoped API |
